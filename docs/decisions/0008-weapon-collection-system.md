# 0008. 武器收集與合成系統：範疇界定與耐用度機制的評估捨棄

## 狀態

已採用（含一項明確捨棄的子功能）

## 背景

武器收集系統的核心需求，是讓玩家在擊敗敵人的過程中持續獲得正向回饋，同時避免無節制的數值成長破壞遊戲平衡。系統涉及三項互相關聯的設計：稀有度掉落機率、同稀有度武器合成強化、碎片兌換。規劃階段另外評估了武器耐用度機制，作為是否加入的候選項目之一。

## 決策

**架構分工**：`WeaponDataSO` 承載武器的基礎靜態數值，透過 ScriptableObject 驅動；`WeaponInstance` 為執行期資料結構，追蹤個別武器實例的合成進度，兩者職責分離，靜態設定與動態狀態不混雜在同一個類別中。

**合成遞減機制**：武器合成強化的數值成長設有上限，避免長期遊玩後數值發散，進而破壞既有的死亡特效等視覺呈現在數值假設範圍內的表現效果。

**稀有度掉落權重動態調整**：已達到上限稀有度的掉落權重會歸零，讓掉落機率自然引導玩家收集尚未收齊的稀有度，不需要額外的強制引導邏輯。

**耐用度機制：評估後捨棄**。判斷依據並非實作難度，而是該機制牽涉至少五項尚未有明確答案的數值平衡設計問題：輕重攻擊消耗速度是否應該不對稱、耐用度是否應與稀有度掛勾、武器損毀時的失落感如何拿捏、是否需要自動替換裝備的操作流程、長期遊玩下武器庫存枯竭的風險如何處理。在這些問題沒有解答的狀態下實作，等同於一邊寫程式一邊設計一套全新的數值經濟系統，風險超出可控範圍，因此不予採用。

## 後果

正面影響：已完成的三項機制（掉落、合成、兌換）形成一個範疇明確、可獨立驗證的收集迴圈，武器資料的靜態與動態分離也讓後續新增武器種類的成本降至新建資產。

負面影響：捨棄耐用度機制意味著武器的長期持有沒有損耗與更替壓力，收集系統在遊戲後期的驅動力主要依賴稀有度收集本身，而非裝備維護這類額外的資源管理層面，遊戲深度在此有明確的取捨邊界。
