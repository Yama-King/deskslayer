# 0003. CPU 效能優化：停用第三方套件內部無條件執行的協程

## 狀態

已採用

## 背景

DeskSlayer 定位為長時間背景執行的桌面陪伴應用，CPU 佔用率是明確的產品需求，過高的背景資源消耗會直接影響玩家在進行其他工作時的使用體驗。桌面透明視窗整合完成後，量測到的 CPU 佔用率高於預期。

## 決策

追查後定位問題來源為 UniWindowController 套件內部的 `HitTestCoroutine()`，該協程不受專案任何設定影響，會無條件在背景持續執行。專案採用的 Alpha 透明模式，使得該協程每一影格都會進入一個成本較高的 GPU `ReadPixels` 分支，但其讀取結果在專案的使用情境下完全沒有被實際消費。

由於該協程屬於套件內部實作，並非公開介面的一部分，透過反射呼叫套件提供的公開 API，一次性停止該協程的執行。

## 後果

正面影響：CPU 佔用率取得約十倍改善，對應了長時間背景執行的產品需求。此案例展示了效能問題不一定源自專案自身邏輯，也可能存在於整合的第三方套件內部，需要具備追查套件內部行為的能力，而非僅檢視自身程式碼。

負面影響：透過反射存取套件內部未公開為正式介面的行為，屬於依賴套件當前實作細節的做法，若套件未來版本更新調整了內部實作或方法簽章，此優化可能失效甚至產生執行期錯誤，需要在套件升級時重新驗證。
