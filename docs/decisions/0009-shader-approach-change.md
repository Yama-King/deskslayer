# 0009. Shader 效果改採手寫 HLSL，不使用 Shader Graph

## 狀態

已採用

## 背景

專案規劃的兩項 Shader 視覺效果——重攻擊蓄力發光與武器揮擊殘影——原先預計使用 Shader Graph 開發，理由是可視化節點編輯對開發效率有一定優勢。但專案的實作流程依賴 Claude Code 透過 Unity MCP 操作 Editor，而 Unity MCP 工具鏈目前僅能可靠地讀寫純文字格式的檔案內容，Shader Graph 的節點資料儲存為 Unity 專屬的圖形化資產格式，無法透過這條工具鏈可靠地建立或修改。

此限制並非在這兩項效果開發時才第一次出現。專案稍早的敵人死亡溶解效果已因相同限制改採手寫 HLSL 完成，並取得可用結果。

## 決策

重攻擊蓄力發光與武器揮擊殘影兩項效果，直接沿用敵人死亡溶解效果建立的手寫 HLSL 開發模式，不再嘗試 Shader Graph 路線。

蓄力發光效果透過 `MaterialPropertyBlock` 將遊戲邏輯數值（蓄力進度）即時傳遞給 Shader，驅動發光強度隨蓄力進度變化；抖動效果獨立於 Transform 位移層級處理，採用連續性雜訊驅動，而非透過動畫補間工具的一次性 Shake API 實作。武器揮擊殘影則採 Alpha 隨時間衰減的做法，搭配物件池管理生成與回收，不使用 `Instantiate`／`Destroy`。

## 後果

正面影響：避免了在已知工具鏈限制下重複驗證同一問題的時間成本，三項 Shader 效果（死亡溶解、蓄力發光、揮擊殘影）採用一致的手寫 HLSL 開發模式，維護與除錯方式統一。

負面影響：手寫 HLSL 相較 Shader Graph，後續若需要新增或調整效果的視覺參數，除錯與試錯的即時性較低，缺少節點編輯器的即時預覽優勢。此外，若未來專案改採其他工具鏈或需要與美術協作調整 Shader，兩者之間目前沒有現成的轉換路徑，重建為 Shader Graph 節點結構需要重新製作。
