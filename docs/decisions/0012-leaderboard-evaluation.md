# 0012. 排行榜功能：評估後捨棄

## 狀態

已捨棄

## 背景

排行榜功能原列於專案規劃的延伸待辦項目，構想是串接 Firebase 建立簡易的分數排行榜，作為小功能之一視開發時程餘裕決定是否實作。

## 決策

評估後決定不予實作，原因有二。

第一，排行榜功能原先預期的技術產出——外接雲端服務、處理非同步請求、管理 API 呼叫的容錯——這項技術需求已經在天氣系統的開發過程中完整達成，排行榜若實作，帶來的邊際技術產出低。

第二，排行榜功能本身存在尚未解決的產品設計問題。DeskSlayer 作為桌面陪伴型遊戲，玩法沒有明確的「一局結束」時刻可以對應到排行榜通常依賴的單次成績概念；此外，若無防刷分機制，排行榜資料的可信度也無法保證。這些屬於設計層面而非工程層面的問題，若未解決便貿然實作，很可能產出一個沒有實質意義、甚至存在漏洞的功能。

## 後果

正面影響：捨棄排行榜將原本規劃給它的開發時間，轉為 W4 階段 Bug 修復的緩衝，以及對既有系統的深度打磨，降低了整體交付風險。

負面影響：遊戲缺少排行榜這類促進玩家之間比較與重複遊玩動機的機制，長期留存與社群互動層面的功能較為單薄。若未來有機會延伸開發，排行榜功能的設計問題（結束時刻定義、防刷分機制）仍需要在實作前重新規劃，並非可以直接沿用原始構想。
